# 문항 텍스트 전환 계획 (PDF 그림 → HTML 텍스트)

작성 2026-11-19. 단계마다 승인을 받고 진행합니다.

## 왜

- **용량:** 사이트 PDF가 700MB이고, 남은 시험까지 더하면 1.3~2GB가 됩니다. GitHub Pages 한도는 1GB입니다. 글자로 바꾼 문항은 1~2KB라서, 그림이 필요한 문항만 작은 그림을 붙이면 PDF 대부분을 없앨 수 있습니다.
- **풀이 화면:** 휴대폰에서 줄바꿈, 글자 크기, 다크 모드를 지원할 수 있습니다. 보기를 누르는 영역도 글자 줄 전체가 되어 정확해집니다.
- **검색 노출:** 문제지별 정적 페이지에 문항 본문을 그대로 실을 수 있습니다. 지금은 발문 첫 줄만 싣습니다.
- **해설 비용:** 해설을 만들 때 문항 그림 대신 글자를 넣으면 입력이 줄어듭니다.
- **0-D:** 스캔본과 HWP 문제지는 글자 층이 없습니다. 같은 변환기로 그림에서 바로 옮길 수 있어 0-D의 길도 열립니다.

## 시범 결과 (2026-11-19, 28문항)

- **표본:** 밑줄·<보기> 상자·법령 낫표·수식·PSAT 표와 그래프·큐넷·공무원 일반을 골고루 뽑았습니다.
- **비교 페이지:** https://claude.ai/artifact/2qKKsXVEHYWW6YDNxwVKSv
- **품질:** Sonnet과 Haiku 모두 보기 개수 28/28을 맞혔습니다. 수식·그림 문항을 빼면 PDF 글자와 98~100% 일치했고, 남은 차이는 빈칸 표기, 표 칸 순서, 붙임표 문자 같은 사소한 것이었습니다.
- **수식과 그림:** 수식은 LaTeX(화면에서 MathJax로 그림)로 옮겼고, 그래프·회로·도면은 그 부분만 원본에서 잘라 그림으로 넣었습니다.
- **모델 선택:** Haiku와 Sonnet의 품질 차이가 거의 없어 Haiku 5.5를 기본으로 씁니다.
- **실행 방식:** 대화 안에서 돌리면 56회 변환에 5시간 사용량의 약 4%가 듭니다. 전체는 API 배치로 돌립니다.

## 방식

### 변환기 `pipeline/convert.py`

명령은 `prepare` / `submit` / `collect` / `status`이고, 해설기 `explain.py`와 같은 구조입니다.

1. **입력:** 문항 영역을 150dpi로 그린 그림과, 같은 영역의 PDF 글자를 함께 넣습니다(글자 확인용). 규격은 시범의 `SPEC.md`를 그대로 씁니다.
   - 허용하는 HTML은 p, br, u, b, i, sup, sub, 상자 div, 표, 수식 `\( \)`, 그림 자리 `<img data-fig>`뿐입니다.
2. **호출:** Message Batches API, `claude-haiku-5-5`, 출력은 JSON 스키마로 고정합니다. 규격 설명은 프롬프트 캐시로 한 번만 계산되게 합니다.
3. **그림 자르기:** 모델이 준 그림 위치(문항 그림 기준 비율)를 PDF 좌표로 바꿔, 원본 PDF에서 200dpi WebP로 잘라 `data/fig/<문제지>-<문항>-f1.webp`에 저장합니다.
4. **자동 검사 (모두 통과해야 텍스트로 씁니다)**
   - JSON과 허용 태그만 썼는지
   - 보기 개수가 시험지와 같은지
   - 수식을 뺀 글자가 PDF 글자와 98% 이상 같은지(빠진 글자가 없는지)
   - 그림 위치가 문항 안에 있는지
   - 모델 자신감이 low가 아닌지
5. **걸린 문항:** Sonnet 5.5 배치로 한 번 더 변환합니다. 그래도 걸리면 그 문항은 지금처럼 원본 그림으로 보여 주고, 목록에 남겨 사람 검수 대상으로 둡니다.
6. **저장:** `web/public/data/text/<문제지 id>.json`에 문항 번호별로 stem, choices, figs, 검사 결과를 넣습니다.

### 사이트

- **풀이 화면:** 문항에 텍스트가 있으면 텍스트로 보여 주고, 없으면 지금의 PDF 영역 보기로 대신합니다. 문항마다 섞여도 됩니다.
  - 보기는 글자 목록을 직접 누르게 하고, 정답·내 답 표시는 지금 스타일을 따릅니다.
  - "원본 보기"는 원본 PDF가 사이트에 남아 있으면 PDF 영역을, 없으면 공식 게시물 링크를 보여 줍니다.
- **정적 페이지:** 문제지별 SEO 페이지에 문항 본문과 보기를 싣습니다.
- **해설기:** 텍스트가 있는 문항은 글자와 그림 조각만 넣어 해설을 만듭니다.

### PDF 정리 (T3)

- 한 PDF를 쓰는 문항이 모두 텍스트로 바뀌면 사이트에서 그 PDF를 뺍니다. 원본은 로컬 `~/Documents/alltests-기출PDF/`와 각 기관 게시물에 남아 있습니다.
- 원본 그림으로 남은 문항이 하나라도 있는 PDF는 사이트에 그대로 둡니다.

## 비용 추정 (API, Haiku 5.5 배치 50% 할인)

- **요율:** Haiku 5.5는 입력 $0.10, 출력 $0.50 / 100만 토큰입니다(프롬프트 10만 토큰 이하). 배치는 그 절반입니다.
- **문항 하나:** 입력은 그림 약 1.5~2천 + 글자 약 0.5~1천 토큰이고, 규격 설명은 캐시로 처리합니다. 출력은 약 1천 토큰입니다. 그래서 문항당 약 $0.0004~0.0008입니다.

| 묶음 | 문항 수 | 추정 비용 |
|---|---|---|
| 시범 묶음 (9급 2026 전 과목) | 약 1,000 | $0.5~1 |
| 공무원 전체 | 약 35,000 | $15~30 |
| PSAT + 큐넷 13종 | 약 27,000 | $10~20 |
| Sonnet 재변환 (걸린 문항, 5~10% 가정) | 약 3,000~6,000 | $5~15 |

정확한 값은 T0에서 실제 토큰을 재서 다시 알려 드립니다.

## 단계 (단계마다 승인 후 진행)

| 단계 | 내용 | 비용 / 사용량 | 끝나면 확인할 것 |
|---|---|---|---|
| **T0 변환기·화면** | `convert.py`, 자동 검사, 사이트 텍스트 보기(PDF 대체 포함), 9급 2026 전 과목 약 1,000문항 실변환 | API 약 $1, 대화 사용량 20~30% | 통과율, 문항당 실제 비용, 사이트에서 풀어 보기 |
| **T1 공무원 전체** | 9급·7급·지방직 약 35,000문항 | API 약 $15~30, 대화 사용량 10% 안팎(제출·수거·표본 검수) | 통과율, 표본 화면 검수 |
| **T2 PSAT·큐넷** | 약 27,000문항(표·그래프가 많아 그림 비율이 높음) | API 약 $10~20 | 같은 항목 |
| **T3 PDF 정리** | 다 바뀐 PDF를 사이트에서 빼고, SEO 페이지에 본문 싣기 | 대화 사용량 10~20% | 사이트 용량, 검색 페이지 |
| **T4 매일 자동** | CI가 새 문제지를 만들면 바로 변환(해설과 같은 단계에서) | 하루 몇 센트 | 첫 자동 실행 |

0-D(스캔본·HWP 문제지)는 T0 뒤에 이 변환기로 그림에서 바로 옮기는 방식으로 다시 계획합니다. 이 경우 글자 대조 기준이 없으므로, 두 번 따로 읽어 같을 때만 씁니다(정답표 읽기와 같은 방식).

## 정할 것 (T0 승인 때)

1. **API 비용 사용:** T0은 약 $1, 전체는 약 $30~65입니다. CI에 연결된 Claude API 조직으로 청구됩니다.
2. **원본 PDF:** T3에서 사이트의 PDF를 빼도 되는지 정해야 합니다. 빼면 "원본 보기"는 공식 게시물 링크로 대신합니다. 원본 PDF를 계속 보여 주려면 외부 저장소(R2 등)가 필요합니다.
3. **"원본 보기" 버튼:** 텍스트 화면에 원본 그림을 볼 수 있는 버튼을 둘지(권장: 둠, PDF가 남아 있는 동안) 정해야 합니다.

## 위험과 대응

- **PDF 글자 층 자체가 틀린 경우:** 글꼴 대응이 잘못돼 다른 글자가 나오는 경우가 있습니다. 모델이 그림과 다르다고 적은 글자는 notes에 남기게 하고, 검사에서 "다름"으로 걸러 재변환합니다.
- **모델이 글자를 고치거나 빠뜨리는 경우:** 98% 대조 검사와 보기 개수 검사로 걸러, 통과하지 못하면 원본 그림을 보여 줍니다.
- **그림 위치 오차:** 그림이 잘리지 않게 위치에 여백을 붙여 자르고, T0 표본 검수에서 그림이 있는 문항을 따로 봅니다.
- **수식 표기 오류:** 수식은 대조 검사로 확인할 수 없어서, 수식 과목은 Sonnet으로 한 번 더 읽어 두 결과가 같을 때만 씁니다(T0에서 필요 여부 판단).
